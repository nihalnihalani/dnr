## 1. Problem

> **"Your repository remembers why. Your agent doesn't."**

A change that was tried and reverted looks like a reasonable cleanup to an agent that never read the ticket. In Django, `ea3a71c2d0` changed `Query.clear_ordering` and `43933a1dca` reverted it, because "self.group_by contains Cols, not aliases" ([reports/orders/README.md](../../reports/orders/README.md)). An agent asked to tidy that method has nothing telling it so.

**Pending:** the GIF of a live block, `reports/video/block.gif`, cut from the filmed `demo/L` run (Phase 14).

## 2. Audience and evidence

DNR is for maintainers of repositories that accept AI-agent changes ([.kiro/steering/product.md](../../.kiro/steering/product.md)). The motivating study is Al Hasan and Biswas, ["What Breaks When LLMs Code?"](https://arxiv.org/html/2605.30777v3) (arXiv 2605.30777), which confirmed 547 coding-agent safety failures.

## 3. How it works

When a Kiro agent's write would bring a reverted change back, the PreToolUse hook [`.kiro/hooks/dnr-pre-write.json`](../../.kiro/hooks/dnr-pre-write.json) runs `dnr check --stdin --hook kiro`. On a match it exits 2, with the reason and links to the original commit, the revert and the ticket.

This works end to end on the real Django case. The re-application of `43933a1dca` exits 2 with edit score 1.00 in `Query.clear_ordering`. The full stderr is in [reports/orders/README.md](../../reports/orders/README.md), and the `R1:` test in [packages/hook/test/golden.test.ts](../../packages/hook/test/golden.test.ts) checks it (hook path built in [b6f3a09](https://github.com/nihalnihalani/dnr/commit/b6f3a09)).

Re-landing a fixed version takes one human approval, through `dnr board` or `dnr allow`. The diagram is in [docs/architecture.md](../architecture.md).

### 3a. Why Frankenstein

DNR stitches four things into one write path: the human arguments in a mid-2000s bug tracker (Django's Trac), deterministic syntax trees (tree-sitter, [vendor/grammars/](../../vendor/grammars/)), git's revert graph ([packages/git/](../../packages/git/)) and a nondeterministic 2026 agent.

### 3b. What surprised us during the build

Only findings that came up while building go here, each linked to its evidence.

- **Test hunks diluted the real order.** Building the real `dnr-43933a1dca` order from Django history pulled in C's test hunk in `tests/aggregation_regress/tests.py` as well as the code change. Orders now skip `test_globs` paths, so the order is the single unit `Query.clear_ordering` (w(A) = 16, R empty), and an exact re-application scores 1.00. Pinned by a test on the real Django texts in [53bb4d7](https://github.com/nihalnihalani/dnr/commit/53bb4d7); see [reports/orders/README.md](../../reports/orders/README.md).
- **The plan named the wrong method.** The plan said the demo revert changes `Query.set_group_by`. Building the order showed it changes `Query.clear_ordering`, so every prompt and doc was corrected ([9a951a2](https://github.com/nihalnihalani/dnr/commit/9a951a2), [reports/orders/README.md](../../reports/orders/README.md)).
- **A case-insensitive path bypass on macOS.** Writing `Django/db/…` instead of `django/db/…` re-applied the change with no block and no Stop. Paths are now resolved to their on-disk casing and case-folded on case-insensitive file systems. Fixed with regression tests in [b3f4301](https://github.com/nihalnihalani/dnr/commit/b3f4301); listed in [docs/threat-model.md](../threat-model.md).
- **Kiro's own permission policy as a second layer.** The wave-3 re-attack showed that a same-user hook can always be worked around. So `dnr init` now offers Kiro `permissions.yaml` deny rules on DNR's own files, with a y/N at the terminal ([88b81bf](https://github.com/nihalnihalani/dnr/commit/88b81bf)). Whether Kiro enforces them headless is spike S17 ([91f5e51](https://github.com/nihalnihalani/dnr/commit/91f5e51), [docs/spikes.md](../spikes.md)), which is **pending**.
- **The first failing property was in our test, not the engine.** P1 failed on its first run because its oracle wrote to a file the order doesn't cover. The engine was right. The fix and the re-run at 500 and 3,000 runs are recorded in [reports/property-failures.md](../../reports/property-failures.md).
- **Browser–hook parity caught a real bug.** The P9 test runs the built `dnr check --file` for every Playground preset on Chromium, Firefox and WebKit. It caught a bug in the matched-units listing ([292e43b](https://github.com/nihalnihalani/dnr/commit/292e43b)).
- **Pending:** spike findings S1–S17, which need `kiro-cli` ([docs/spikes.md](../spikes.md)).

## 7. Limits

From [docs/threat-model.md](../threat-model.md#known-limits):

- Order files (`.dnr/orders/*.json`) are committed and readable, so an agent can read every order's A and R tokens and tune a paraphrase to land under τ. The MCP tools' hiding of A and R does not protect them. The mitigations are proximity (§5.6) and measured held-out recall (gate check 2), not secrecy.
- A rename or move that the fingerprint index cannot match, below its similarity floor, falls to the warn tier.
- guard-shell is partial: it is a parser, not a sandbox. The Stop backstop narrows the shell route but does not close it.
- An agent can still skip the pre-commit hook through paths guard-shell does not parse: environment tricks for other hook managers (`HUSKY=0`-style), a script file that runs `git commit --no-verify`, `python -c "subprocess…"`, or setting `core.hooksPath` with an editor tool in a git config outside `.git/config` (for example `~/.gitconfig`, which is outside the protected globs).
- Under `commit-enforce`, pre-commit is the only local enforcement. The server-side Crew check is the backstop.
- The Kiro-variable list used by the R6 self-approval check is provisional until spike S8 (`packages/hook/src/ancestry.ts`, `KIRO_AGENT_VARS`). The check also refuses any wrapper between `dnr` and the nearest interactive shell, so `npx <package> allow` is refused too; humans need a global install.
- A human's mid-session edits to a file the agent also touched are scored together with the agent's.
- Trial agents run as the same OS user as the harness; isolation is by path, a per-run HOME and `chmod` lockdown, not by OS account.
- Processes outside Kiro can edit anything.
- Fail-open lets writes through when DNR itself hits an internal error or timeout (by design: a DNR bug never stops an agent). Invalid or tampered DNR state does not fail open (R7 as amended; review C1).
- Under `--trust-all-tools`, an `ask` may be auto-approved (spike S5).
- A non-browser process running as the same user can read the board's cookie jar. It can also read the 0600 launch file and request its one-shot URL before the browser does; it then gets the nonce, and the browser shows an expired launch.
- The Kiro permission deny rules that `dnr init` offers depend on Kiro's glob resolution and shell capability name, which spike S17 has not verified yet.
- The human-only guard is a speed bump against a careless agent, not a security boundary against a hostile same-user process; DNR detects and flags such approvals. Known escapes: interpreter code that talks to the board on a computed port (guard-shell R7 matches only literal ports), `osascript` run from inside Python, and a renamed copy of the `dnr` binary. The ancestry guard refuses that copy unless it is double-forked, and the grant it then creates is flagged suspect.
- On the `127.0.0.1` board fallback (Safari, `--host 127.0.0.1`), the cookie is shared with other loopback ports.
- MCP tools that write files bypass pre-write: Kiro's `write` category covers only built-in file write tools, and Stop's `touched` set does not include MCP writes. A follow-up `@mcp` PreToolUse hook that sends path-bearing calls to the warn tier is an open option (`hook-contracts.md`).
- A `PermissionRequest` hook from another source can auto-answer prompts. It cannot override a PreToolUse exit 2 or `deny`, so `deny` format is unaffected. In `ask` format, another hook could approve DNR's prompt (spikes S5 and S15).
- Kiro's matcher `write` is also an unanchored regex, so a tool whose ID merely contains "write" reaches the hook; DNR treats an unknown tool with no path as allow.
